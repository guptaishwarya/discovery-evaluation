# Two-Journey Framework

## Purpose

Evaluate whether a proposed AI capability addresses meaningful user friction.

## User Journey

Discover → Evaluate → Decide → Act → Experience

## AI Capability Journey

Information → Recommendation → Personalization → Prediction → Action → Automation

## Trigger

Use when the builder is selecting, escalating, or comparing AI capabilities.

## Core question

Where is the user friction, and does this AI capability actually solve it?

## Evaluate

- user journey stage
- user friction
- proposed AI capability
- why AI is useful
- intersection strength
- mismatch
- simpler sufficient capability
- key validation question

## Challenge

Ask whether the capability is being added because it solves friction or simply because it is technically possible.

If a simpler capability solves the same friction, prefer the simpler capability.

## Output

- user_journey_stage
- friction
- ai_capability
- intersection
- reasoning
- mismatch
- simpler_sufficient_capability
- key_question

## Constraints

- Do not assume AI is necessary.
- Do not equate advanced AI with better product value.
- Do not treat agent as an AI maturity stage.
- Focus on user value.
