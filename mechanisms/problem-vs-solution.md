# Problem vs Solution

## Purpose

Separate the underlying user problem from the proposed solution.

## Trigger

Use when the builder is describing or committing to a feature/product/implementation before the problem is sufficiently clear.

## Core question

What problem are you actually solving, and for whom?

## Reasoning

Establish:
- user
- user goal
- current behavior
- friction
- why the friction matters
- evidence
- proposed solution

If the builder is using the solution as evidence of the problem, challenge the distinction.

Useful challenge:

"Would this problem still matter if your proposed solution did not exist?"

## Output

Return structured findings:

- problem
- user
- user_goal
- current_behavior
- friction
- evidence
- proposed_solution
- problem_clarity
- critical_unresolved_question

## Constraints

- Do not invent evidence.
- Do not validate the solution simply because it sounds useful.
- Do not ask for every field at once.
- Keep the interaction conversational.
